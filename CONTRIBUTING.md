# Contributing

## Ветки

- `main` — единственная долгоживущая ветка. Всегда в состоянии «зелёная»:
  все проверки проходят, релиз пригоден к развёртыванию.
- Работа ведётся в коротких тематических ветках: `docs/contributing`,
  `feat/releases-api`, `fix/context-guard`.
- Имя ветки: тип через косую черту и краткое описание.
- Ветка живёт недолго: создаётся под задачу, удаляется после слияния.
- Прямые пуши в `main` запрещены. Любое изменение попадает в `main` только
  через pull request.

## Pull request

- Один PR — одна логическая задача. Рефакторинг не смешивается с новой функцией.
- Описание PR объясняет, что изменено и зачем, а не только что изменено.
- PR не сливается, пока не проходит CI.
- Требуется минимум одно подтверждение (approve) от другого участника.
- Слияние — только squash-merge, чтобы в `main` не появлялись merge-коммиты.
- После слияния ветка удаляется.

## Формат коммитов

Заголовок: `тип: описание`.

| Тип | Когда применяется |
| --- | --- |
| `feat` | новая функциональность |
| `fix` | исправление дефекта |
| `docs` | документация |
| `chore` | инфраструктура, зависимости, рефакторинг без смены поведения |
| `test` | тесты и тестовая инфраструктура |
| `build` | сборка, зависимости, конфигурация сборки |
| `ci` | изменения пайплайна |

Правила:

- Описание в нижнем регистре, без завершающей точки.
- Длина заголовка не больше 72 символов.
- Заголовок самодостаточен: по нему понятно изменение без чтения diff.
- Тело отделяется пустой строкой и объясняет «почему», а не пересказывает «что».

```text
chore: initial project scaffold with base CI pipeline
feat: add releases endpoint with filtering by status
fix: verify kube context name before deleting clusters
docs: record pinned k3s version in environment notes
```

## Локальные проверки

Перед открытием PR:

```bash
make check
```

Запускает lint, проверку типов и тесты. Ровно эти же команды выполняет CI,
поэтому локальный результат совпадает с результатом пайплайна.

## Секреты

- Реальные пароли, токены, kubeconfig и дампы не попадают в репозиторий.
- Локальные значения хранятся в `.env`, который исключён через `.gitignore`.
- В репозитории лежат только примеры: `.env.example`,
  `deploy/local/secret-values.example.yaml`.
- Если секрет попал в историю, удаления файла недостаточно: значение считается
  скомпрометированным и подлежит замене.

## Review

- Ревью проверяет корректность, читаемость и безопасность, а не вкус
  в оформлении.
- Автор не подтверждает собственное изменение.
- Все обсуждения закрываются до слияния.

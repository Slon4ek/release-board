# ADR 0001. Выбор веб-фреймворка

- Статус: принято
- Дата: 2026-10-04

## Контекст

Сервис `release-board` — небольшой HTTP API поверх PostgreSQL. Все операции
сетевые: соединение с базой, ожидание ответа. Клиентом будет pod в Kubernetes,
поэтому важны задержка ответа и расход ресурсов. Нужны автоматическое описание
API для отладки и для будущего клиента, а также возможность подменять зависимости
в тестах.

Кандидаты: FastAPI, Flask, Django REST Framework.

## Решение

Выбран **FastAPI**.

## Обоснование

1. **Асинхронность нативная, а не обёртка.** FastAPI построен на ASGI и работает
   с `async` без адаптеров. PostgreSQL вызывается через `psycopg` асинхронно,
   поэтому один обработчик не блокирует цикл событий на сетевом ожидании.
   У Flask путь к асинхронности потребовал бы ASGI-обёртки поверх WSGI, то есть
   по сути другого фреймворка.
2. **Один источник правды о контракте.** Форма запроса и ответа описывается
   аннотациями типов, и из них же генерируется OpenAPI. Забытый эндпоинт не
   попадёт в спецификацию, а расхождение документации с поведением невозможно
   по построению.
3. **Валидация входящих данных из коробки.** Pydantic 2 отклоняет некорректные
   `version` и `environment` до входа в обработчик, а `response_model` не даёт
   утечь наружу лишнему полю ORM.
4. **Встроенная подмена зависимостей.** `dependency_overrides` позволила проверить
   ответы 404 и 409 без поднятия базы: подменяется только получение сессии.
5. **Строгая типизация.** Pyright в режиме `strict` проходит без ошибок на всём
   пакете `src`, включая сервисный слой и обработчики исключений.

## Альтернативы

**Flask.** Зрелый и минималистичный, но синхронный. Асинхронный доступ к базе
потребовал бы либо потоков, либо перехода на ASGI-обёртку, а спецификацию API
пришлось бы собирать вручную. Отклонён.

**Django REST Framework.** Богатый стек: ORM, админка, миграции, аутентификация
из коробки. Для микросервиса из восьми операций это избыточно: админка не нужна,
ORM всё равно заменена на SQLAlchemy ради асинхронности. Отклонён.

## Последствия

### Положительные

- спецификация API генерируется из кода, `/docs` и `/openapi.json` работают сразу;
- весь ввод-вывод асинхронный, один event loop вместо пула потоков;
- доменные ошибки отделены от HTTP-кодов: сервисный слой бросает
  `ReleaseNotFoundError` и `InvalidStatusTransitionError`, а HTTP-слой переводит
  их в 404 и 409 в одном месте.

### Отрицательные

1. **Pydantic становится обязательной частью домена.** Файл `schemas.py` — это
   «бланк на столе»: то, что наружу приходит и наружу уходит. `models.py` — это
   наша запись в базе. Сейчас запись в базе тянется к бланку, чтобы узнать
   список допустимых статусов. Это обратная зависимость: если завтра появится
   CLI или фоновая задача, использующая ту же базу, ей придётся тащить
   классы веб-запроса ради одного перечисления.
   *Решение:* вынести перечисления и таблицу переходов в отдельный модуль
   домена, который импортируют и ORM, и схемы. Тогда никто не зависит от чужого
   описания внешнего мира.
2. **Правка схемы немедленно меняет публичный контракт.** Аннотации
   одновременно являются валидацией и спецификацией. Добавили поле в
   `ReleaseResponse` — оно сразу стало частью публичного API. Добавили колонку в
   модель, не исключив её из `response_model`, — утечка внутренних полей. Это
   одновременно и достоинство, и ловушка: спецификация меняется без отдельного
   шага «обновить контракт».
3. **Асинхронность возлагает ответственность на разработчика.** FastAPI считает,
   что обработчики `async`. Если внутри вызвать блокирующую функцию, весь
   event loop встанет — и вместе с ним **все** запросы, а не только этот.
   У Flask медленный запрос занимает один поток, здесь он занимает всех.
   Обнаружится это не в тестах, а под нагрузкой.
   *Решение:* держать асинхронность единой — никаких блокирующих вызовов базы и
   сети в слоях ниже HTTP. Сейчас это выполняется: `psycopg` в асинхронном
   режиме, SQLAlchemy с экстрой `asyncio`.
4. **Нет админки и готового интерфейса.** Django даёт `/admin` с пользователями,
   формами и фильтрами бесплатно. FastAPI даёт `/docs` — это SwaggerUI для
   вызова API, а не интерфейс для человека. Для этого сервиса нормально,
   потребитель — pod. Но если когда-нибудь понадобится посмотреть доску в
   браузере, его придётся писать отдельно.
5. **Многие базовые вещи придётся собирать самостоятельно.** Аутентификация с
   ролями, ограничение частоты запросов, фоновая обработка — у Django это
   готово, у FastAPI ответ обычно «возьми стороннюю библиотеку». Сборка
   собственного стека — это и свобода, и риск: каждая добавленная зависимость
   сама по себе требует обновлений и проверки уязвимостей.
